# 公司标志缓存与行情展示性能（2026-09-06）

基于 PR #133 的 `5df015191c7f71de72ecd8a9f2cf6e3980deb451` 继续优化，不更改雷达逐笔证据或 5 分钟确认规则。

## 公司标志

原逻辑为按股票依次尝试 3 个可信图片源（类别股可能 6 个），每次创建 HTTP 客户端；成功缓存 24 小时且只有进程内副本。前端已优先使用内置图片，没有为了标志查询公司资料接口。

新逻辑：

- 本地内置图片继续优先。外部图片保留原有可信来源，不增加付费密钥、公司资料查询或 Finnhub 普通行情调用。
- 每个未命中标志最多两个源同时竞速，成功后取消其余请求。全应用共用连接池，至多六个上游请求同时执行；总请求期限 12 秒，单次网络超时 4 秒，逐次验证跳转、类型及 512 KiB 大小上限。
- 成功结果缓存 72 小时；写入 `DATA_DIR/company-logos.sqlite`，使用已有持久卷。进程重启、部署重建不会清掉这份缓存（前提是不删除持久卷）。
- 三天后先返回旧图，站长请求触发一次异步刷新，最多额外保留七天。访客只能读取已有缓存，不能触发外部抓取。不存在的标志负缓存一小时；临时网络错误只在内存中短暂缓存一分钟，不误存成“公司不存在”。
- 浏览器响应有三天缓存、七天 stale-while-revalidate、原始 Age 和 ETag；未变化时返回 304。内置静态图片沿用原有静态缓存策略。
- 标志内存副本至多 128 项且总图片内容不超过 16 MiB。磁盘缓存至多 2048 项且总图片内容不超过 64 MiB，数据库页和临时事务日志另有少量开销。此上限不是整个后端进程的内存上限。
- 缓存不可写或损坏时，仍可返回已下载的图片。负缓存、磁盘配额、并发请求去重、访客权限及安全跳转均有回归测试。

第一次遇到未缓存的公司仍受图片源覆盖和网络影响；不能保证每家都有图，也没有凭空承诺真实网络的加速倍数。

## 行情

- 上游仍只有一条共享连接；同一批成交不折叠、不丢弃。每 128 条让出一次事件循环执行权，避免无 I/O 的大批成交独占事件循环，之后继续顺序判断全部成交。
- 页面仍按原来的 250 毫秒节奏合并。不以降采样雷达或降低更新频率换性能。
- 普通推送仅发送本轮变化股票。同一轮、同一股票的展示对象只构建一次，相同订阅集合复用消息。首次订阅、分配变化仍发完整状态。
- 慢客户端队列仍有容量上限；发生丢弃后发重同步通知和完整报价快照，清除过时队列；雷达仍从持久状态恢复。增量推送不能假定每条消息都能到达。
- 前端连接状态只按实际使用字段比较，忽略 as_of、last_message_at 等诊断时间戳带来的无意义全局重绘。报价时间本身仍保留。
- 重复注册相同股票不重建 SSE。超过 200 个客户端代码时，新增超额代码仍立即显示定时更新。
- 数字整体与数位使用 React.memo，原有稳定数位键、250ms 滚动、小数和首屏真实值不变。改用 CSS transform transition，不再为每一位创建 JavaScript 动画器。系统减少动态效果时用纯文本，移除十行数字列。
- 公司标志组件也被记忆化，不因同页价格变化重复执行。
- 图表实时参考线只在价格、标签或历史图表本身变化时调用 setOption；仅成交时间戳改变不重绘参考线。
- 长时间跨页面浏览会淘汰无订阅的旧报价及雷达缓存，保留当前使用的数据。

## 验证与测量

新增测试覆盖：三天持久缓存、重启复用、负缓存、上游竞速取消、六请求上限、内存及磁盘配额、过期回退、公共读权限、304、安全跳转、增量推送与类别股别名、慢读者补齐、1000 条成交全部保持顺序、时间戳更新不重建数字列、重复订阅、减少动态效果。

`PYTHONPATH=backend python scripts/benchmark_quote_fanout.py` 是可重跑的合成微基准：100 个客户端，每个页面 46 只股票，分别测一只变化与全部变化。比较的旧路径为优化前完整页面快照循环。它测量消息构建时间、构建次数、逻辑报价条数和 JSON 大小，不测用户实际设备帧率、不测生产服务器总 CPU，也不包含 TLS/TCP 传输开销。全部股票同时变化时，报价数量本来就不能减少。

现有历史行情、期权、分析刷新、雷达数据库、访问权限、免费额度规则和页面订阅范围不变。是否需要进一步扩容，仍应结合生产环境的实际并发用户、CPU、事件循环延迟、内存与浏览器长任务监测决定。
