## 必须修复

### P1-A 指数 `change_percent: null` 三角契约断裂

**声称（B-LOG-6）：** 指数缺少有效昨收时保留最新价，将涨跌幅留空。

**生产者已做到。** `backend/app/api/market.py` 在缺昨收或昨收非有限时返回 `None`，不再用 0 冒充平盘：

```python
"change_percent": round((price - prev) / prev * 100, 2) if prev is not None else None,
```

**消费者未对齐，本 PR 也没有改这两处：**

| 消费者 | 位置 | 实际行为 |
|---|---|---|
| 公开首页快照 | `backend/app/public_home_snapshot.py` `_validate_indices` 约 500 行 | 有价时要求 `_finite_number(change)`。`change_percent is None` 使整包 `create_public_home_entry('indices')` 抛 `ValueError: invalid public home payload: indices`。访客首页 503 或继续吃旧快照。 |
| 前端映射 | `frontend-src/src/api/modules/market.ts` `mapIndices` 约 42 行 | `price === null \|\| changePct === null` 丢行。`IndexTape` / 首页指数卡永远看不到「有价无涨跌」。 |

`public_home_snapshot.py` 在本 PR 只补了财报 `estimate_sources`，没有改 `_validate_indices`。个股 `_validate_overview` 已允许 optional change，指数没有。

独立复现（审查环境）：

- `_validate_indices(有价 + change_percent=null)` → `False`
- `create_public_home_entry('indices', mixed)` → `ValueError: invalid public home payload: indices`
- `mapIndices` 丢弃 `change_percent` 为 `null` 的行

`70f06e0` 未修 Codex 对 `6e0b067` 的同一条 P1。

**修复方向：** 与个股概览同一契约。有价无涨跌视为合法；前端渲染价格并显示涨跌未知，不要丢行，不要让 worker 整包失败。

### P1-B N2 不完整：短暂身份 503 清空已登录自选

**声称（N2）：** 同身份核验及暂时无法读取身份时保留页面。

**页面实例保留，列表不保留。** `Layout.tsx` 的 `pageKey` 只用 `pathname` / `role` / `username`，不含 `identityUnavailable`，因此不 remount，顶栏仍显示「退出 alice」。真正清数据的是身份失败后的状态机。

链路：

1. `frontend-src/src/hooks/useAccess.tsx` 约 121 行：失败时 `setQueryPrincipal(null)` + `setIdentityUnavailable(true)`。注释写「保留当前已知身份」，实现把查询主体置空。
2. `frontend-src/src/hooks/usePersonalWatchlist.ts`（本 PR 未改）约 15、83 行：`identityUnavailable` 时 `enabled = false`，不再暴露已缓存 `tickers`；`error` 合成为「身份暂时无法确认，请稍后重试」。
3. `frontend-src/src/pages/Watchlist.tsx` 约 378–386、804–847 行：`enabled: !personal.error` 停行情；`personal.error` 时 `items = []`；`personalFailed` 整页换成 EmptyState「自选读取失败」。

行情失败路径已经区分「还有上一轮数据时不整块换错误页」；名单/身份失败没有同等保护。

独立 Playwright（live Vite `127.0.0.1:3148`，`VITE_API_MODE=live`，alice 已登录且名单含 AAPL；focus 后拦截 `/access/status` 为 503）：

| 指标 | 失败前 | 失败后 |
|---|---|---|
| `[data-quote-symbol="AAPL"]` | 1 | 0 |
| 「自选读取失败」 | 0 | 1 |
| 「身份暂时无法确认，请稍后重试」 | 0 | 1 |

主区同时出现「0 只标的 / 上限 50」「暂时读不到你的自选列表，请重试。」「自选读取失败」。顶栏身份未变。

现有 E2E（`audit-principal-scope`）只断言选股草稿在身份扰动后仍在，**没有**断言已登录自选列表仍在。催化 `frontend-src/src/components/catalysts/useCatalystResource.ts` 约 20、44 行在 `identityUnavailable` 时返回空快照 + 503，同类风险。

**修复方向：** 短暂身份失败应保留上一份已确认名单与行情，只加横幅和重试；不要把合成的 `personal.error` 当成「名单不存在」。`queryPrincipal` 在短暂失败时不应清空。应补浏览器断言：已登录自选在 `/access/status` 503 后列表仍在。
