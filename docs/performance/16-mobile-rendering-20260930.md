# 手机掉帧、新闻首屏与雷达初始布局

本轮针对滚动和页面切换时的持续渲染开销，以及手机竖屏进入雷达后按钮移位的问题。源码和正式前端构建产物已更新；未部署到生产服务器。

## 改动

- 自选页时钟、雷达扫描倒计时移入独立组件，秒级变化不再驱动整页重渲染；切到后台时停止时钟，恢复可见时立即对时。
- 手机报价直接显示准确读数，不再为每一位数字创建十个滚动字形；统计数字也不再每帧更新 React 状态。桌面仍保留数字动画。
- 自选的表格模式只挂载当前屏宽对应的布局，手机不再同时维护隐藏表格和可见卡片；旋转或调整窗口仍能切回桌面表格。
- 手机取消大面积毛玻璃、页面位移、曲线描边动画和高度插值，保留交互反馈。屏宽订阅共用一个原生媒体查询监听器。
- 图表尺寸相同不重绘，同一帧的尺寸变化合并；点击回调更新只重绑事件，不再重设整个图表。手机画布像素密度上限为 2，关闭数据过渡动画，降低高密度屏幕的栅格绘制开销。
- 新闻页的股票影响、经济日历、数据源和详情抽屉按需加载。手机新闻行在数据到达后直接显示，移除逐行等待入场的时间；关闭抽屉仍保留原有退出与焦点恢复流程。
- 雷达页头取消位移动画，手机状态区固定网格和占位高度，选择背景直接显示在当前按钮位置，避免数据到达、折行和布局投影叠加造成漂移。

## 对照结果

基线为 `dcf2956b` 工作树原有正式构建。候选为本轮正式 live 构建；具体文件名和 SHA-256 见[原始结果](artifacts/mobile-20260930.json)。本机 Chromium、390 × 844、DPR 3、4 倍 CPU 限速，同一份 32 只自选模拟数据，前后交替顺序共 4 对样本。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 自选卡片视图 main 内元素数 | 4,683 | 1,220 |
| 报价内元素数 | 2,112 | 160 |
| 实际呈现的报价数 | 32 | 32 |
| 手机表格模式 main 内元素数 | 9,392 | 1,219 |
| 手机表格模式同一股票的报价副本 | 2 | 1 |
| 静置 2.2 秒脚本执行时间，中位数 | 104.65 ms | 10.62 ms |
| 静置 2.2 秒主线程任务时间，中位数 | 216.29 ms | 40.18 ms |
| 新闻页与公共依赖静态 JS，gzip -9 | 267,921 B | 259,637 B |

卡片视图节点减少约 74%，报价数量不变。上述计时是小样本本机实验，不是实际手机帧率或现场 INP；新闻包大小只计静态 JS 导入闭包，不含样式、接口数据和后续动态加载。新闻接口响应时间仍取决于服务端和网络，本轮没有声称消除该等待。

## 验证

- 正式构建、TypeScript、构建产物一致性及静态断言通过。Lint 无错误，雷达页原有两条 effect 依赖提醒保留。
- 全量前端行为测试 1,159 项通过，无失败或跳过。
- 行情、自选和新移动端回归 32 项通过；多尺寸页面、深浅外观、弹层、焦点与动效回归 37 项通过。
- 新测试覆盖 320px / 390px 雷达状态加载前后控件位置（偏移不超过 1px）、移动/桌面布局切换、新闻未使用模块不提前请求、抽屉打开和关闭、图表回调变更不重绘或重置缩放、事件解绑及实例销毁。

复现浏览器专项：在 `frontend-src` 执行 `npm run test:quotes`。本机已有 Chromium 时可设置 `OPTIX_PLAYWRIGHT_EXECUTABLE_PATH`。

性能对照：分别用 `scripts/perf/serve_frontend_fixture.py --root <构建目录> --port <端口>` 服务两个正式构建，再执行 `node scripts/perf/measure_mobile_frontend.mjs`。默认端口为 3055 / 3057；可通过 `BASELINE`、`CURRENT`、`BASELINE_DIR`、`OUT` 指定本地地址和结果路径。脚本拒绝非本机地址，使用隔离的固定响应，不连接生产接口。
