## 用户任务预算（实验室须标注，不冒充 RUM）

新闻页最严。骨架屏 / spinner 消失不算完成。

| 指标 | 目标 | 计时定义 |
|------|------|----------|
| LCP | ≤ 2.5s（移动/桌面分组看 p75） | PerformanceObserver largest-contentful-paint |
| INP | ≤ 200ms | 实验室用可重复交互延迟代替，不把 Lighthouse TBT 写成 INP |
| CLS | ≤ 0.1 | layout-shift（hadRecentInput 除外） |
| `news_content_ready` 冷启动参考移动档 | ≤ 2.5s | 从导航开始到首条真实新闻标题可见且按钮可点 |
| `news_content_ready` 有效缓存再进入 | ≤ 1.0s | 同上；须同时记录「旧缓存可见」与「按既有时效完成刷新」 |
| 筛选/搜索/分类 | 输入到正确结果可用 | 不含只转圈 |
| 原卡顿路径 | 可感知耗时下降 ≥ 30% | 基线已良好则不强行凑百分比 |

同时记录：首屏 JS/CSS、请求数、传输体积、长任务、渲染次数、DOM、内存、滚动帧、交互延迟。

## API 预算（修改前按基线填具体数字）

分 API、负载档、缓存命中分别记 p50/p95/p99、错误率、查询次数、上游次数。普通读与重计算不能用同一武断阈值。

初始调查阈值（不是验收放宽口）：

| 接口 | 规模 | 关注 |
|------|------|------|
| `GET /api/catalysts/feed` limit=12 | n=100 / 1k / 10k | 延迟应随窗口物化成本上升；优化后须保持 items 集合与游标语义 |
| 同接口 limit=50 window=24 | 同上 | 对应 newsToday |
| `GET /api/catalysts/status` | 任意 | 应保持有界 |
| 其他公开读 | 代表路径 | 相对基线恶化 > 5% 触发复查 |

HTTP 200 不够：断言条数、游标、中文可见性、`as_of` / `data_through` 时效字段。超时、429、5xx、空数据计入结果。

## 正确性对照

技术指标、期权、筛选、排序、信号、交易时段与时区：固定输入前后比对，数值容差在各实验记录里预先写出。新闻排序稳定性：同 `published_at` 的次序、新插入、重复加载、后台恢复、手动刷新。

## 不退化

关键指标变差超过 5%（超测量噪声）触发复查，不单次判定。无收益且增复杂度则回滚。
