# 加载提速与版面稳定

日期：2026-10-09。分支 `claude/perf-frontend-2026-10-09`，基于 `origin/main` `72f426f0`（与当日生产一致）。改后的测量对象是本分支最后一个代码提交 `3718d903` 的 `frontend/`（入口 `index-CD-p3IhI.js`）。

目标：8 个页面 × 桌面、手机两档共 16 个组合，累积布局偏移（CLS）都低于 0.05，加载中除跑马灯外没有按钮挪位；每页 JS 请求从 37–42 个降到 15 个以内，下载总量不增加；公司标志不再走接口。

## 结论

- 版面：生产数据即时回放下，16 个组合的 CLS 从 0.000–0.328 降到 0.000–0.015；延迟回放从 0.005–0.862 降到 0.000–0.022；演示数据构建从 0.000–0.502 降到 0.000–0.011。三种测量面下，首屏内的非跑马灯控件漂移改后都是 0 个（改前即时与延迟回放为 0–13 个）。
- 英文、日文界面（各一轮）：CLS 改后最高 0.018 / 0.037（改前最高 0.624 / 0.410）；首屏控件漂移改后最多 1 个（新闻页手机，以及日文自选页手机首屏底边的一张卡片），见下文。
- 请求：每页 JS 文件从 35–41 个降到 8–9 个（含空闲预取与主题脚本）；JS 块 57 → 23 个，gzip 总量 910.8KB → 899.9KB。实测每页下载的 JS（解压后）少 9–29KB。代价：首屏前就要下载的 JS 多了 5–34KB（gzip）；算上空闲预取，每页总量仍比改前少 6–14KB（gzip），见「分包」与「没有做的」。
- 标志：即时回放一轮 16 次页面打开里，标志接口请求从 29 个降到 0 个（改前集中在财报页与雷达桌面）。

## 测法

不打生产站（读接口限流 200 次/60 秒）。三种测量面：

- **生产数据回放**（主口径）：2026-10-09 22:02 在生产站（即改前构建）把 16 个组合各打开一次，录下 `/api/`、`/static/` 的响应（HAR）。之后由本地静态服务分别托管改前（`origin/main` 的 `frontend/`）与改后的构建，浏览器按录制内容回放这些请求，录制里没有的直接中止；首页经济日历的请求带当天日期，过了零点后把录制里的日期窗口改成测量当天的窗口。即时回放跑三轮取中位数；另跑一轮延迟回放：每个接口按生产源站耗时加 150ms 往返再返回（热点 4.6s、新闻流 2.3s、个股新闻 2.1s、技术指标 1.4s 等），数据按真实先后到达。
- **演示数据构建**：不设 `VITE_API_MODE` 的构建，数据来自 `src/mocks`，不请求接口。用同一个静态服务托管，改前、改后各两轮取中位数。
- **构建产物图**：读 `vite build` 输出的分块和静态依赖，算每个页面首屏前要下载哪些块、空闲预取之后一共下载哪些块。

浏览器为 Chrome（Playwright 驱动）。界面语言以中文为主，英文、日文各另跑一轮即时回放（浏览器语言 en-US、ja-JP）。桌面 1440×900；手机为 iPhone 14 视口，处理器降速 4 倍。

- CLS：布局偏移接口（Layout Instability API）在打开后约 9.5 秒内的累计值。
- 首屏控件漂移：打开后 0.3–8 秒的 9 个采样点之间，位置变动 ≥4px 或尺寸变动 ≥8px 的按钮、链接、输入框个数。跑马灯里的控件不计，只计变动前或变动后落在首屏内的。2026-10-09 生产基线里的「漂移次数」包含跑马灯和首屏以下的控件，口径更宽，不能与本表直接相减。
- JS 文件与字节：同一时间窗内实际下载的全部 JS，含空闲时预取的常用页面和主题脚本。生产站另有一个 Cloudflare 统计脚本，本地不计。

## 做法

### 版面稳定

原则：读取中的骨架和读到后的内容占同样的位置；读到前就知道会出现的东西先占位；会随数据变长的说明不跟标题、按钮挤在一行。没有用「整页等数据到齐再显示」来压分数。约定写进了 `docs/UI_DESIGN_SYSTEM.md` §11。

- 指数行情带：基金价格与涨跌各叠在一个等宽的隐形样例上（`$0000.00`、`−10.01%`，纯文字，不带滚动数字的字形），「—」换成读数时芯片不变宽，后面的芯片不动；右侧说明的三种文案叠在同一格，取最长的宽度。
- 页脚：主区至少一屏高，页面骨架偏矮时页脚也不进首屏（原桌面 CLS 的主项）。
- 页头：手机上元信息单独一行（`PageHeader`），「正在读取交易时段…」和读到后的「● 盘前」不再让标题行在一行与两行之间来回；新闻页只有刷新按钮，用 `inlineMeta` 保持与标题同排。
- 财报：读取中也渲染「财报日程」标题行和周 / 月切换；周历日格固定留足三只代码加「+N」（165px），骨架按同样的表头与日格高度排。
- 突破雷达：手机状态区改两列网格，每项从首帧起占位（时段标签、下次扫描、数据截至两行）；桌面把范围切换单独放第二行，状态行每一项按读取中与读到后各种文案里最宽的一种占位，英文、日文文案更长时读到前后也在同一处换行；读不到快照时活跃条数显示「—」；去掉页头入场位移；数据覆盖条在快照读取期间先占位；「默认排序」一行在手机上留两行，跟随默认时快照未到前按试用排序的完整说明叠一份隐形样例留出行数，仍不猜服务端默认算法。
- 自选：两张评分卡加涨跌卡、市场分析卡的骨架按真实卡片的行盒排；评分缺失时评分卡照常占位、显示「—」，不再整张去掉（演示数据没有评分，手机上整排曾矮 146px）；多列卡片里报价说明固定排在价格下面（参考价换成实时报价时说明变长，原来会把行业标签挤到下一行，整排卡片变高 28px）。
- 个股：读取中按读到后的版式排（操作行间距、手动更新入口、K 线卡与关键数据卡、技术指标六格）；手机上价格独占一行、「较昨收」再起一行、报价时间单独一行；去掉页头入场位移（读取中与读到后是两棵树，页头会重挂）。
- 首页：数据覆盖条计数格按「99/99」留宽、状态说明在手机上单独一行；研判卡在读取中为模型与时段标签留位，骨架撑到首屏以下。
- 指数卡（首页、大盘）：当日小图放进零高度容器，有没有小图卡片都一样高。小图只在演示数据里有，原来会把下方内容推下 9px。
- 新闻：来源状态四格留出读到后的常见高度；热点带一行固定为热点卡高度（骨架、空态、读取失败、真实卡片都撑满这一行）；热点追踪骨架撑到首屏以下。
- 大盘：指数骨架按两组排（美股三张、其他两张）；交易时段卡、走势评分卡有同尺寸骨架。
- 选股：候选池未读到时分档计数与扫描按钮显示「—」，不再显示假的 0；计数格留宽；走势评分卡有同尺寸骨架。
- 列表行与卡片的入场改为只淡入、不位移（指数卡、自选卡、雷达信号与重点卡、雷达历史事件、财报行、新闻行、周历日格、月历日格、选股结果、新闻股票影响与来源、热点追踪逐股、CTA 概览、财报影响分节）。这些位移会被「控件漂移」计成按钮挪位。
- 新增两个共享件：`SkeletonLine` 在与真实文字同一字阶的行盒里画骨架条；`SameWidth`（由指数行情带提出）把几种可能出现的内容叠在同一格，格子取最宽的一种。

### 分包

`vite.config.ts` 的分块计划改为四块加图表：

- `index`：从 HTML 入口算起的全部静态依赖合成入口块本身（React、路由、词典内核、主题偏好、路由预取）。原来跟入口并行下载的 `prefetchRouteChunk` 块（60KB，内容是入口依赖里被应用壳共用的部分）不再单独存在。
- `app-shell`：不变，仍在 `prepareI18n()` 之后加载，入口不静态引用它（构建期检查照旧）。
- `menu-select`：Radix 下拉及其依赖只有五个页面用（雷达、新闻、选股、个股、自选），单独成块，首页、财报、大盘不下载它。没有换成自写的下拉：`feedback-layout`、`ui-review`、`overlay-behavior` 等规格依赖它的列表框语义与焦点行为，替换应单独做。
- `page-shared`：被两个及以上页面（含页面里按需加载的面板）静态引用的模块合成一块；会静态带上图表模块的不进来，首页、选股不连带 ECharts。只被一个页面用的模块留在该页面块里，`eps-chart` 保持单独的可重试地址。
- framer-motion 留在应用壳：壳层自己在用（全局动效配置、手机底栏、滑块），几乎所有页面也在用，拆出去不减少任何页面的下载量。

新闻页的股票影响、经济日历、消息来源、管理设置与详情抽屉改为按需加载（采纳 #204），新闻页块 102KB → 54KB；抽屉第一次打开时才下载，之后常驻，保留关闭动画与焦点恢复。

### 公司标志

## 没有做的

- **首屏前的 JS 字节**：`page-shared` 把两个以上页面共用的模块合成一块，当前页用不到的部分也在首屏前下载，首屏前的 gzip 字节比改前多 5–34KB（见上表）；空闲预取结束后，每页总下载量仍比改前少 6–14KB。若要压回去，可按页面族（带图表的页面、列表页）把它拆成两块，每页多一个请求。
- **K 线卡内部增高**：`/stocks/{t}/technical` 晚于 K 线数据到达时，图表下方出现副图控件和指标副图，卡片变高约 60–75px，右栏关键数据卡的「52 周区间」跟着下移（个股桌面 CLS 约 0.015–0.022）。要等分析结果才知道副图有几格，提前占位需要改 `KlineChart` 的布局计算，留作单独改动。
- **财报右栏**：财报影响卡读到分析后变高，推动下方 EPS 图占位（桌面 CLS 约 0.006）。
- **英文、日文的固定高度**：新闻页来源状态四格、自选页评分卡标签在英文、日文下比中文多折行（见「英文与日文界面」）。评分卡标签是已知文字，骨架可以直接显示标签、只给读数画骨架条，任何语言下行数都一致；来源状态的文字随数据变，要按语言留高度或改成固定行数截断，本轮都没改。
- **雷达桌面状态行**：各项宽度已固定，剩下的是同一格里「—」换成读数时文字的微小重排（CLS 约 0.001–0.002，不含按钮）。
- **指数行情带先请求指数行情**：报价状态未知时行情带先拉 `/api/market/indices`（源站约 0.46s），状态到达后改显示基金；非首页、大盘页上这次请求是白拉的。改法是在报价仓库里记「已探测」并在演示数据、身份不可用时退回，涉及行情仓库的测试，留给后续。即时回放下会因此看到一次约 0.001 的偏移，真实网络下状态总是先到。
- **首屏以下的控件漂移**：长内容读到后，首屏以下的按钮会下移（不可见，不计 CLS）。即时回放下剩下的主要是：财报月历 30 个日格按钮（上方列表读到后变长 292–342px）、手机个股的指标说明按钮、手机大盘宏观区的切换按钮（部分轮次）、手机首页经济日历、选股扫描按钮与价格输入框（上移 4–12px）。
- **下拉换轻量实现**、**应用壳再瘦身**：见「分包」。`useAccess` 为清缓存引用了整个 `catalysts/api`（约 10KB），命令面板（约 6KB）也可以按需加载；两者合计 gzip 约 4KB，收益小，未动。
