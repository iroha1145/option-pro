# 任务书摘录

完整目标见用户下发的 `/goal` 文本。这里只冻结本工作区必须遵守的边界。

## 要回答的问题

1. 选股排序是否把更值得关注的股票排在前面？优势出现在哪些期限与环境？
2. 雷达是否及时识别后续有价值的突破，而不是给已经上涨的股票贴标签？
3. 两者结合是否有增量？发布后、扣成本、资金守恒后还剩多少？

## 允许

- 补齐研究工具、修复有证据的实现错误、增加测试、隔离候选配置。
- 使用既有授权的公开日线源做有界下载并缓存。
- 向生产扫描器注入时钟与离线行情，使回放与线上共用 `_scan_sync` / `detect_base` / `detect_breakout`。

## 禁止

- 自动改线上默认评分、权重、阈值。
- 自动开启 Range Persistence 或其他 shadow。
- 部署、合并 `main`、下单、购买数据、扩大付费 API 预算。
- 另写一套更容易赚钱的简化算法冒充原项目回测。
- 提前查看封存区收益并回头调参。
- 用触发价冒充成交价；用合成数据宣称胜率。

## 证据等级

| 等级 | 含义 |
|------|------|
| A | 当时 completed + published_at 快照回放 |
| B | 同一生产逻辑 + 当时可见历史输入的反事实重建 |
| C | 当前主题池 / 仅日线 / 缺 Discovery 等降级研究 |
| D | 合成数据，只测程序 |

本环境没有生产 `optix.db`，因此雷达 Grade A 暂不可用。选股也没有历史扫描 JSON 时间序列。默认结论口径是 **C（股票池）+ B（评分/检测数学）**。
