# 市场研判提示词调整说明

本地候选版本为 `market-brief-prompt-v3`。2026 年 10 月 11 日核对以下 Claude 官方文档后，针对四份真实存档中的重复标题、摘要与要点重叠、跨日时间指代和新闻来源混用作了调整。

## 官方建议如何应用

- [通用提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) 的清晰说明、提供任务背景与正向格式要求：说明首页和历史阅读场景，分别定义标题、摘要、要点、观察项与整体反证的作用。
- 同一指南的示例与标签建议：标题改用三个正向示例，覆盖少数权重领涨、上涨扩散及证据不足，并用 `<examples>` / `<example>` 区分；明确这些是虚构写法，不能作为行情事实。保留已有 `<untrusted_market_evidence>` 标签与第三方材料边界。
- [Claude Opus 5.5 专页](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5) 讨论了第三方输入边界和推理过程要求：本次只要求研判结论与事实依据，不增加输出内部推理过程的指令；模型、推理强度和请求设置均保持原样。标签只是材料边界提示，不能替代程序校验。
- [提示词工程概览](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview) 强调先定义成功标准并测试。本地现有测试检查提示词稳定性、请求格式与结构化输出兼容；这些检查不能证明实际报告质量已改善。

## 本项目的取舍

标题通常 25—45 字、摘要通常 80—140 字是首页排版目标，不是 Claude 官方字数标准，也不是新增校验限制。复杂情况可以在现有硬上限内多写，数据缺失、时效、覆盖范围和关键矛盾应完整保留。证据充分度仍由现有字段呈现；不要求条目写满。

跨日报告写清所属交易日与撰写日期；事件使用具体月日及已知美东时间，不补造时刻。关键新闻只使用对应的 `news:` 或 `hot:` 编号；网页补充事实归入相关分析段并写明来源，主题、突破、日程和财报编号继续用于各自事实，不能充当新闻来源。数值仍由程序证据提供，条件中的“且/或”关系与阈值保持原意。

本次没有触发真实模型生成、没有改写历史报告，也没有部署或修改服务器。新提示词的实际长度、引用准确性和信息完整度仍需以真实生成结果验证。
