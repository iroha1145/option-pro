## 1. 相对强弱比较了不同日期

**触发条件：** 个股与标普500指数基金（SPY）缺少不同的日线，或个股最新价格比基准落后。原代码分别取两条序列各自最后20日或63日的收益，再相减；删除缺失行会进一步改变比较的起点。

**影响：** 价格路径相同，也可能算出跑赢或跑输。回归样本中，只删除个股窗口内一根日线，20日结果从应有的0变成了0.63个百分点；让基准多出一天上涨而个股尚未更新，结果变成了−112.22个百分点。这些数值来自人为构造的测试样本，不是对真实行情的判断。

**修复：** 从个股窗口取得起止交易日，再取基准同日价格。带时区的日线按纽约交易日匹配。基准任一端点缺失、非有限数或非正价格时，返回缺失值，不用邻近日期补位。基准中间某一天缺失但两个端点都在时，仍可计算这两个端点间的收益。

涉及文件：

- `backend/app/services/daily_returns.py`
- `backend/app/services/strength/features.py`
- `backend/app/services/signals.py`

验证覆盖20日与63日两条入口、个股缺日、基准缺日、个股行情落后、基准起止端点缺失，以及不同数据源的时区表示。相关用例位于 `tests/test_relative_strength_alignment.py`。

## 2. 有效价格不足时仍尝试生成评分

**触发条件：** 历史表行数达到最低要求，但收盘价全为空、全为无穷值，或清理后只剩很少的有效价格。

**影响：** 全部清空后访问最后一行会抛出索引异常；部分清空时，原来的样本数量检查也不能阻止过短序列进入后续计算。

**修复：** 在访问收盘价和生成特征前检查列是否存在，并按清理后的有效价格数量执行最低样本要求。数据不够时返回缺失结果。

涉及文件：`backend/app/services/strength/features.py`。回归测试覆盖空值、正负无穷值，以及原表100行但仅10个有效收盘价的情况。

第1、2项合计新增16条测试，修改前14条失败、2条通过，修改后全部通过。

## 3. 预期波动借用了无关合约的报价时间

**触发条件：** 同一期权链内，不同行权价或看涨、看跌两侧的报价时间不同。原实现取整条链第一条或最新一条报价时间判断新鲜度，再从链内另选合约计算跨式组合（Straddle）。

**影响：** 无关的新报价会让旧报价或没有时间的合约被标为有效；反过来，第一条旧报价也可能挡住实际可用的新报价。展示的观察时间可能比参与计算的某一侧报价更新。

**修复：** Massive与MarketData的数据适配保留每个合约自己的报价时间。计算前逐合约检查，新报价不再替无关合约证明有效；最终展示所选看涨与看跌合约中较早的时间。无法解析的时间戳按缺失处理。保留现有数据源优先级、价差检查和时间上限。

涉及文件：

- `backend/app/services/massive.py`
- `backend/app/services/earnings_enrichment.py`

`tests/test_expected_move_quote_times.py`新增8条测试，修改前7条失败、1条通过，修改后全部通过。覆盖无关新报价与旧报价、缺失报价时间、有效组合不会被其他旧合约阻挡，以及展示时间确实来自所选组合。

**数据限制：** 雅虎财经（Yahoo Finance）当前适配只提供整条链的获取时间，不能据此证明每一笔交易或报价都是实时的。本次修复不把该获取时间解释为逐笔成交时间。

## 4. 强制刷新后，自动请求返回但页面不再更新

**触发条件：** 使用页面的强制刷新后，请求版本增加，但定时器与页面恢复可见事件仍保存最初的请求版本。

**影响：** 后续请求可以成功返回，结果却被版本检查丢弃。页面停留在手动刷新那次的数据，用户难以从页面察觉定时刷新已经失效。

**修复：** 自动刷新使用当前请求版本，仍保留旧请求不得覆盖新结果的检查；获取函数的引用在渲染提交后更新。

涉及文件：`frontend-src/src/hooks/usePolling.ts`。在 `frontend-src/tests/use-polling-forced-refresh.test.mjs` 中增加定时触发与恢复页面可见两种行为测试。修改前两条都出现“已请求第3版，页面仍显示第2版”；修改后，与原有两个旧请求竞争测试一起通过，共4条。
