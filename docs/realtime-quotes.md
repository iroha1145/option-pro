# 实时行情与突破雷达

实时行情在后端统一接收。同一个股票代码出现在顶部、雷达或多个访客页面中时，只占一个 Finnhub 订阅名额。浏览器只连接本站，不接触行情密钥。

## 启用

先按既有密钥管理流程配置 `FINNHUB_API_KEY`，再调整 `config/personal.toml`：

```toml
[quotes]
enabled = true
public_enabled = false
signals_enabled = true
max_symbols = 50
publish_interval_ms = 250
release_seconds = 30
```

重启后端与后台任务，使两者使用同一份配置。三个开关默认均为 `false`，旧配置缺少 `[quotes]` 段时也保持关闭。

- `enabled`：允许使用实时报价界面。关闭后恢复既有定时行情。
- `signals_enabled`：逐笔成交是否可以推进雷达“已触发”状态。关闭后保留定时扫描，不再新增实时触发。
- `public_enabled`：是否向非站长访问者展示实时行情及实时衍生信号。仅在具备数据共享授权后打开；它不会单独启动行情服务。

当前 [Finnhub 个人方案](https://finnhub.io/pricing)提供 50 个实时订阅、每分钟 60 次普通查询。一个密钥同时只允许一条实时连接。公开分享行情及衍生结果需要[书面授权](https://finnhub.io/terms-of-service)，普通个人付费套餐不自动包含这一权利。本项目默认只允许站长验证，不通过用户注册状态绕过这个边界。

当前部署仍使用一个后端进程。文件锁阻止同一数据目录、同一密钥建立重复连接；多副本部署前应把行情接收独立成共享服务，不能直接增加后端副本。使用相同密钥的其他程序也会占用上游唯一连接，本站无法在它们之间协调。

## 订阅与报价

名额顺序为：顶部 `SPY、QQQ、DIA、IWM` → 已触发的有效雷达事件 → 其余雷达候选的现有排名 → 当前详情及弹窗 → 当前页面列表。总数不超过 50。相同级别保留请求到达顺序。

选股页订阅当前分页的全部股票；自选页订阅当前筛选后的整个列表，包含尚未滚动到的行。未获名额的股票仍保留定时行情，并标注更新方式。切换页面会更新订阅集合，浏览器进入后台或关闭后，专属名额在 30 秒内释放。雷达不依赖页面是否打开。

实时成交逐笔处理，页面每 250 毫秒合并一次报价。无新成交时不会生成数字跳动，也不会把长时间无成交误报为连接中断。报价使用成交时间与接收时间两个时钟，旧查询结果不能覆盖更新的成交价。涨跌以对应交易日的正常交易昨收为基准；昨收缺失时显示缺失，不填零。盘前盘后显示实际交易时段；是否有持续成交取决于数据源覆盖。

数字采用逐位滚动，首次直接显示真实价格。后续变化支持小数、负号、千位分隔；相同价格不重复播放。系统设置“减少动态效果”时直接更新。报价变化不改变列表顺序，技术指标、历史蜡烛图与期权仍按各自数据周期更新。

## 雷达证据

定时初筛继续使用既有 5 分钟频率和市场过滤。合格实时成交越过已有门槛后，观察事件可以进入“已触发”；同批成交随后跌回也不会抹去已观测的触发。

“已确认”和“失效”仍依赖完整的 5 分钟行情及原确认规则。成交推送中的数量不会被当成完整市场成交量，也不会补造断线期间的蜡烛图。确认的实际时效仍受原行情来源影响。

原扫描快照保持不变，实时状态和状态变化单独保存。定时扫描使用同一份完整行情校验实时事件，事务中的版本和证据时间检查阻止旧扫描覆盖较新的实时状态。关闭公开行情时，访客读取原扫描结果，不会获得站长实时触发的价格、时间或来源。

## 接口

- `GET /api/quotes?symbols=AAPL,MSFT`：只读行情缓存；不创建临时订阅。无代码时返回启用与访问状态。
- `GET /api/quotes/stream?symbols=AAPL,MSFT&focus=AAPL`：本站来源的服务器推送事件连接；`focus` 必须属于本次 `symbols`。

推送事件类型为 `quotes`、`status`、`radar`。报价包含价格、比较基准、涨跌、成交时间、接收时间、来源、交易时段与更新方式。状态中的 `allowed` 决定当前用户是否应建立实时连接。接口不公布其他访客的订阅代码。

每次最多登记 200 个代码，服务器同时最多接受 256 个行情订阅客户端，每个来源地址最多 8 条页面连接；超额返回可重试的限流响应。每 15 秒发送保活消息，断开后回收订阅；站长会话到期时停止发送私有实时数据。

当前页面超过 200 个代码时，浏览器先登记顶部基金、焦点股票和其余列表，未登记部分显示定时行情。类别股的 `BRK-B` 与 `BRK.B` 等写法共享一个上游订阅，页面保留原代码。供应商明确未返回有效报价时显示定时回退，不因连接已建立而标为实时。

定时扫描产生的确认和失效状态每秒从已提交记录中同步到行情服务；新连接会补回最近状态。浏览器断线重连或事件队列溢出时重新读取雷达快照，打开的事件详情同步补齐时间线。

行情流使用 `Cache-Control: no-store, no-transform` 与 `X-Accel-Buffering: no`。反向代理应关闭此路径的缓冲与缓存，并允许超过 15 秒的持续响应。正常接口压缩继续保留，事件流不压缩。

普通 Finnhub 查询共用 `/data/finnhub-budget.sqlite` 中的滚动额度，涵盖实时报价初始化、基本面、财报日历、历史补齐与密钥验证；收到限流后向各进程共享冷却时间。数据库只保存密钥哈希。行情密钥和上游错误原文不会进入公开接口。

## 验证和回退

本地测试使用模拟成交流，不消耗真实账户订阅。开市验证需确认：顶部与个股有效成交持续到达；收盘后状态正确；多人重复代码去重；超过名额时明确回退；断网恢复后不倒退或重复触发。目标是收到上游成交后通常在 1 秒内显示，供应商自身延迟另行测量。

```bash
PYTHONPATH=backend python -m pytest -q
node --experimental-strip-types --test frontend-src/tests/*.test.mjs
npm --prefix frontend-src run lint
npm --prefix frontend-src run test:quotes
```

持续集成同时运行原有界面回归和实时行情浏览器用例；后者只连接本机模拟接口。

异常时分别关闭 `signals_enabled` 或 `enabled`，然后重启相关进程。已保存的扫描快照不会被清空；实时记录保留用于追溯，公开展示仍受独立开关控制。
